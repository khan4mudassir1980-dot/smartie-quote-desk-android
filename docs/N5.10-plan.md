## 3. The six hazards — as approved, with A and B folded in

1. **Edit never goes through the finalise gate.** It has its own path,
   `QuotationWriteRepository.edit`: one transaction, `update()` never `set()`,
   no counter. `ensureFinalised` refuses an edit draft. Pinned: "an edit saved
   really changes the stored lines — and the number and the counter do not
   move".
2. **Its own draft slot.** The edit draft's id is the quotation's id, and it
   carries `editOf = {quotationId, number, rev, opened disc.amt,
   opened discBase}`. `QuoteDrafts.retire` closes it, falling back to the
   draft in progress. One edit at a time.
3. **Two editors.** `rev = opened + 1`, and the rule requires
   `stored + 1`. The in-transaction compare gives the loser's sentence, and
   the edit draft stays.
4. **The rules.** The sketch below.
5. **"Last edited — <name>, <d MMM yyyy, h:mm a>"** on the detail card, right
   after the date, and an "Edited" tag on the list row. N5.11 prints it.
6. **Cancel is remote-first**: a transaction. It uses V8C4's confirm text,
   answered "Cancel quotation" / "Keep it", and V8C4's toast. The row turns
   Cancelled only when the listener brings it.

```
function qnCreator() {
  return resource.data.get('byUid', '') != '' && resource.data.byUid == mine();
}

// --- cancel: V8C4's three keys (Q4), and never twice (amendment B) ---------
function qnCancel() {
  return touched().hasOnly(['status','cancelledBy','cancelledAt'])
    && resource.data.get('status', '') != 'Cancelled'      // B: history stands
    && request.resource.data.status == 'Cancelled'
    && request.resource.data.cancelledBy is string          // Q4: a name
    && request.resource.data.cancelledAt is number;         // Q4: the device's clock
}

// --- the discount, split so an edit can apply the cap only when raised -----
// discountOk() keeps its meaning exactly: every 9a cap test passes unchanged.
function discountShapeOk() { /* discountOk's structure: amount 0, or amount
  and base numbers, base >= 0, base <= subtotal + amount, amount <= base */ }
function discountWithinCap() { /* exists(quoting) &&
  amount <= base * discountCap() / 100 + 1 */ }
function discountOk() {
  return discountShapeOk() && (amount == 0 || admin() || discountWithinCap());
}

// Amendment A. Against the STORED document (`resource.data`), never a value
// the client supplies. Raised = added, or the amount rose by more than a
// rupee, or the rate rose — the new amount exceeds the old rate applied to
// the new base by more than a rupee (9a's margin), cross-multiplied so no
// division. Anything unreadable before counts as raised: fail closed.
function qnDiscountRaised() {
  let before = resource.data.get('disc', {}).get('amt', 0);
  let baseBefore = resource.data.get('discBase', 0);
  let after = request.resource.data.get('disc', {}).get('amt', 0);
  let baseAfter = request.resource.data.get('discBase', 0);
  return after > 0 && (
    !(before is number) || before <= 0
    || after > before + 1
    || after * baseBefore > before * baseAfter + baseBefore);
}

function qnEditKeys() { /* hasOnly the Q3 list */ }
function qnEditStamped() {
  return touched().hasAll(['rev', 'lastEditedAt'])
    && request.resource.data.get('lastEditedByUid', '') == mine()
    && request.resource.data.get('lastEditedBy', null) is string
    && request.resource.data.get('lastEditedAt', null) is number
    && request.resource.data.get('rev', -1) == resource.data.get('rev', 0) + 1;
}

allow update: if
  // cancel (Q1: the creator, or Owner/Administrator on anyone's)
  ((admin() || (member() && !worker() && qnCreator())) && qnCancel()
     && request.resource.data.no == resource.data.no
     && request.resource.data.total == resource.data.total)
  // edit
  || (member() && !worker() && (admin() || qnCreator())
     && resource.data.get('status', '') != 'Cancelled'
     && qnEditKeys() && qnEditStamped()
     && request.resource.data.lines is list
     && request.resource.data.subtotal is number
     && request.resource.data.total is number
     && discountShapeOk()
     && (admin() || !qnDiscountRaised() || discountWithinCap()));
```

**The shape still applies when the cap does not**, so a claimed `discBase`
stays bounded by `subtotal + amount`. That bound limits how far an inflated
base can hide a rate rise, to the transport slack already recorded for 9a. It
is stated again, not new.

## 4. Amendment A — the cap on an edit

**Where it lives, twice, by the same arithmetic:**

- **The rule**: `qnDiscountRaised()` above, against `resource.data`.
- **The app**: `QuoteDiscount.raised(beforeAmt, beforeBase, afterAmt,
  afterBase)`, pure. `QuotationEdit.plan` calls it **against the stored record
  read inside the transaction**, and passes the Manager's cap to `refusal()`
  only when it answers raised (`QuoteMath.NO_CAP` otherwise). The builder calls
  it as a courtesy against `editOf`'s opened figures, so its warning agrees
  with what Save will do. The transaction decides.

**The tests**, on both sides (emulator and `QuoteDiscountTest` /
`QuotationEditTest`). Setup: a Manager's quotation issued at 10% of 34,000
(`disc.amt` 3,400). The Owner then lowers the cap to 5%. *(The figures were
renumbered in N5.12's scrub, 2026-10-07; the arithmetic is the same.)*

- **(i)** Only a phone number fixed: accepted, though 3,400 is past the new
  cap.
- **(ii)** Raised to 12% (4,080): the cap applies — refused. The witness: a 3%
  quotation raised to 4% is accepted.
- **(iii)** Lines added to 51,000, 10% unchanged (5,100): the amount rose —
  refused. **Deliberate**: otherwise new items get the old over-cap rate.
- **(iv)** A flat ₹1,500 kept while lines fall to 17,000: the rate rose
  (1,500 × 34,000 > 1,500 × 17,000 + 34,000) — refused.
- **(v)** Lines removed to 17,000, 10% unchanged (1,700): accepted. **With
  rounding**: 10% of 34,010 (3,401), then of 17,005 (1,700.5 → 1,701). The
  check is 1,701 × 34,010 = 57,851,010 against 3,401 × 17,005 + 34,010 =
  57,868,015, so not raised — **only because of the rupee margin**.
- **Added where there was none**: raised.
- **Owner or Administrator** past the cap: accepted.

## 5. Amendment C — Duplicate

- **Offered on every issued quotation, cancelled ones included**: cancel
  then duplicate is how a quotation is reissued. It is never offered on a
  draft (the history lists none). It is not offered while an edit is open:
  "Finish or discard your changes to X first".
- **V8C4's question when the draft in progress has lines**: "Replace the
  quotation you are working on with a copy of this one?" Yes replaces it; an
  empty draft is replaced without asking. **The copy always takes a new id**
  (R15).
- **Copies** the lines, the party **with its link** (`partyId`), and the
  tier. **Not** installation or discount. **Carriage is restored** to the
  transport field and note (Q5; the same recogniser as edit). **GST is not in
  V8C4's list**, so the copy starts at the builder's default: Include GST on,
  and the rate resolved from the products or asked for. Say if the copy should
  carry the stored GST instead.
- **Rates — what reprices, and when:**
  - **On opening: nothing.** Each line's own tier is set to the copy's tier,
    so `alignDraftToTier`, which runs when the catalogue arrives, finds
    nothing out of step. Pinned (R24).
  - **One tap on Dealer / Client** reprices every catalogue-priced line to
    **today's** catalogue (`QuoteDraft.withTier`) and says "N repriced, M kept
    at your rate". Lines whose V8C4 rate differed from `origRate` come back
    typed-by-hand and are kept. A product that has left the catalogue becomes
    "Rate needed".
  - **Tapping + on a product already on the copy** raises that line's
    quantity **at its copied rate**.
  - **Picking a customer** does not move the tier on a copy, because it has
    lines (§6).
  - **Seen, not guessed**: a copy carries `copiedFrom = {number, at}`,
    appended to the draft codec. The builder shows "Rates as quoted on X,
    <date>. Switching Dealer / Client reprices at today's rates." An edit
    draft shows the same line for its own number.
- **Toast — Q7.** V8C4's words name download, print and share, which do not
  exist here until N5.11. Recommend "Copied into a new draft — it takes a new
  number when it is finalised" now, with V8C4's exact words restored in N5.11
  as a recorded requirement.

## 6. Amendment D — the party type

**On the quotation:**

| Case | What happens |
|---|---|
| Pick a saved **Dealer/Client** on a quotation with **no lines** (not an edit) | The rate follows the type — V8C4's own rule (6604); nothing to reprice |
| Pick one on a quotation **with lines** (a copy included) | The rate stays. A note (ours): "<name> is saved as a Dealer — this quotation stays at Client rates. Switch above to reprice." |
| Pick one on an **edit draft** | The rate stays (Q6), with the same note |
| Pick a legacy **contractor** (or unknown type) | The rate stays, and nothing is said |
| **Save this customer, new** | Asks "Save <name> as a Dealer or a Client?" — Dealer / Client / Cancel. There is no default and nothing is saved without an answer (V8C4 used the tier: a divergence, recorded). The answer sets **only the customer's type**; the quotation's rate stays where the switch is, with the note if they differ |
| **Save this customer, existing** | The type is never written — already true (D2), and still pinned |
| **The switch** | Changes only this quotation's rate. Never a customer's type |

`PartyWrite.create` refuses an unstated type ("Choose Dealer or Client") in
place of V8C4's `client` fallback. It accepts only `dealer` or `client` for a
new party.

**On the Parties screen — checks only, as the Owner chose:**

- **Add**: the type offers Dealer and Client only, **none selected**, and
  Save is refused until one is chosen.
- **Edit**: the stored type is shown selected and can be changed. A stored
  `contractor` (or unknown) type shows none selected, and **Dealer or Client
  is asked for** — Save is refused until chosen.
- **Add and Edit** run `PartyFormat`'s GSTIN, phone and email checks, shown
  bare as "Save this customer" shows them.
- **Nothing else**: no merge question, no name restriction, no archived
  rule. **Recorded, not fixed:** the Owner accepted that a Manager renaming a
  party is refused after Save.
- The rules cannot tell a quotation's write from the Parties screen's, so
  "the type changes only on the Parties screen" is the app's guarantee,
  pinned by D2's test and R30.
